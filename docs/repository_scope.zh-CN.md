# 仓库边界与首次推送

本仓库只包含 MathCoffee 可复用框架，明确排除视频素材和单期视频完整实现。
原本地制作工程及其 Git 历史单独保留；首个框架提交没有父提交，因此不会把旧历史
里的场景代码带到远程。只推送已审查的框架引用，不能使用 `--all`、`--mirror`
或在框架发布时顺手推旧分支与标签。

## 纳入

- 共享时间轴、音频、声音、程序配乐与标签契约。
- 无单期输入依赖的通用 CLI、测试与双引擎合成器。
- 通用词典／配置、依赖锁、上游声明与制作约定。

## 排除

- `media/`、`scenes/`、`examples/`、`notebooks/` 与单期 authoring、数学模型、
  旁白、字幕、编辑计划、封面、交付和验收记录。
- 图片、视频、音频、字体、模型权重、归档包和生成缓存。
- 虚拟环境、node_modules、凭据、环境变量文件、测试私钥与本机数据库。
- 历史中直接永久清空媒体目录的清理工具。

`.gitignore` 是第一层忽略；[repository-files.txt](../repository-files.txt) 是经审查的
精确清单。`scripts/repository_guard.py` 检查 Git 索引中的真实内容，或指定提交及其
历史，拒绝清单外文件、禁止路径／后缀、符号链接、大文件、二进制和常见密钥标记。
该检查不能识别所有隐私内容，也不能自动判断新文件是否属于某一期，仍需人工审查。

```sh
make repository-check
.venv/bin/python scripts/repository_guard.py --ref HEAD --history
```

后续新增通用文件时，先审查内容、许可证和对单期目录的依赖，再更新精确清单并
显式 `git add`。不要从原制作工程的旧分支推送；框架开发在独立工作树继续。
本地制作材料被忽略只是版本边界，绝不意味着允许删除。
